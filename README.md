# Техническое задание: приложение SleepTracker

## 1. Цель проекта

Разработать консольное Java-приложение для анализа данных о сне пользователя.
Приложение должно загружать журнал сна из файла, вычислять показатели на основе записей и выводить результаты анализа в консоль.

Основные требования к приложению:
- Возможность добавлять новые аналитические функции с минимальными изменениями существующего кода.
- Возможность независимо тестировать каждую аналитическую функцию.
- Использование функционального подхода при обработке данных.
- Отсутствие циклов `for` и `while` в основном коде приложения. В юнит-тестах циклы разрешены.

## 2. Входные данные

### 2.1. Формат входного файла

Приложение получает путь к файлу через аргументы командной строки.
Файл содержит записи о сессиях сна. Каждая запись включает три поля:

| Поле | Формат | Описание |
|---|---|---|
| Время засыпания | `dd.MM.yy HH:mm` | Дата и время начала сессии сна |
| Время пробуждения | `dd.MM.yy HH:mm` | Дата и время окончания сессии сна |
| Качество сна | `GOOD`, `NORMAL`, `BAD` | Оценка качества сна |

Поля разделяются символом `;`.
Пример содержимого файла:

```text
01.10.25 22:15;02.10.25 08:00;GOOD
02.10.25 23:00;03.10.25 08:00;NORMAL
03.10.25 14:30;03.10.25 15:20;NORMAL
03.10.25 23:30;04.10.25 06:20;BAD
```

Записи в файле упорядочены по дате и времени.

### 2.2. Обработка данных

При запуске приложение должно:
1. Получить путь к входному файлу.
2. Прочитать файл.
3. Преобразовать записи в представление, пригодное для дальнейшего анализа.
4. Передать загруженные данные аналитическим функциям.

Все аналитические функции должны работать с данными, загруженными из файла.

## Этап 3. Выявление бессонных ночей

### 4.7. Подсчёт бессонных ночей

**Назначение:** определить количество бессонных ночей за весь период наблюдения.

#### Определение периода наблюдения

Период наблюдения начинается в момент начала первой сессии сна в файле и заканчивается в момент окончания последней сессии сна.

Предполагается, что пользователь постоянно носит умные часы и все сессии сна за этот период присутствуют в файле.

#### Правило определения бессонной ночи

Для каждой ночи рассматривается интервал времени с `00:00` до `06:00`.

Ночь считается бессонной, если в этом интервале не было ни одной сессии сна, пересекающей его границы.

Примеры:

| Сессия сна | Результат |
|---|---|
| 23:00–03:00 | Ночь не считается бессонной |
| 02:00–07:00 | Ночь не считается бессонной |
| 07:00–11:00 | Ночь считается бессонной |

#### Определение первой ночи для анализа

При определении первой ночи учитывается время начала первой сессии в файле:

- Если первая сессия началась после `12:00`, первой потенциальной ночью считается следующая ночь.
- Если первая сессия началась до `12:00`, первой потенциальной ночью считается предыдущая ночь.

#### Требования к функции

**Входные данные:** список сессий сна.

**Результат:** целое число — количество бессонных ночей за период наблюдения.

**Тестирование:** минимум четыре юнит-теста.

Тесты должны проверять основную логику функции и граничные случаи.

Функцию необходимо подключить к общему механизму запуска аналитики.

## Этап 4. Определение хронотипа пользователя

### 4.8. Классификация отдельных ночей

Для каждой ночи необходимо определить один из трёх хронотипов:

- `OWL` — сова;
- `LARK` — жаворонок;
- `PIGEON` — голубь.

Классификация выполняется по времени засыпания и пробуждения.

| Хронотип | Условия |
|---|---|
| Сова (`OWL`) | Время засыпания позже `23:00` и время пробуждения позже `09:00` |
| Жаворонок (`LARK`) | Время засыпания раньше `22:00` и время пробуждения раньше `07:00` |
| Голубь (`PIGEON`) | Все остальные случаи |

При классификации необходимо игнорировать:
- бессонные ночи;
- дневные сессии сна.

### 4.9. Определение хронотипа пользователя

После классификации ночей необходимо определить наиболее часто встречающийся хронотип.

**Входные данные:** список сессий сна.

**Результат:** один из трёх хронотипов — `OWL`, `LARK` или `PIGEON`.

#### Правила определения результата

1. Определить хронотип каждой учитываемой ночи.
2. Подсчитать количество ночей каждого хронотипа.
3. Выбрать хронотип с наибольшим количеством ночей.
4. Если два или три хронотипа встречаются одинаково часто, результатом должен быть `PIGEON`.

Функция должна возвращать значение, обозначающее хронотип пользователя.

### 4.10. Подключение функции

Функцию определения хронотипа необходимо подключить к общему механизму запуска аналитики.

Результат должен выводиться в консоль в понятном пользователю виде.

Date & Time API
1. LocalDate — дата, LocalTime — время, LocalDateTime — дата и время без зоны.
2. Instant представляет конкретный момент времени.
3. ZonedDateTime учитывает правила часового пояса.
4. Duration описывает временную длительность, Period — календарный промежуток.
5. DateTimeFormatter отвечает за преобразование даты и времени в строку и обратно.
6. Unix timestamp в секундах преобразуется через Instant.ofEpochSecond(), в миллисекундах — через Instant.ofEpochMilli().
7. При переводе события в другой часовой пояс используй withZoneSameInstant().
8. Объекты java.time неизменяемы: результат plusDays(), plusHours() и подобных методов нужно сохранять.
